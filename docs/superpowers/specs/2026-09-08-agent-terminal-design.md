# エージェント向けターミナル termit 設計仕様

作成日：2026-09-08
状態：設計確定、実装未着手

## 1. この文書が定めるもの

コーディングエージェントを常用する開発者のためのターミナルエミュレータを設計する。
既存のターミナルは、人間が一つのシェルに向かって対話することを前提に作られている。
エージェントを使う開発者は、同じリポジトリに対して複数のエージェントを同時に走らせ、ある地点から分岐させ、隔離環境に閉じ込める。
この文書は、その使い方に必要な機能だけを持つターミナルの仕様を定める。

名称は **termit** とする。
当初は `tex` としていたが、組版システムの TeX と綴りが衝突するため、公開にあたって改めた。

## 2. 設計の柱

五つの制約が設計全体を支配する。

**左ペインがある**：実行中のセッションの系統と、直近のコマンドを常時表示する。

**エージェント向けである**：セッションの分岐と隔離が、キー一つで届く位置にある。

**余計な機能がない**：第 3 節に列挙したものを作らない。

**軽量で高速である**：単一バイナリ、起動 200ms 以内、常駐メモリ 100MB 以内を目標とする。

**自分でビルドできる**：`cargo build --release` 一回で完成する。
ビルド時に Node.js や Python を要求しない。

## 3. 非目標

次のものを作らない。
将来の要望として保留するのではなく、この仕様の範囲では作らないと決める。

- タブ
- 任意の分割とタイル管理（レイアウトは左ペインと端末ペインの二領域に固定する）
- 合字（リガチャ）と可変幅フォント
- 画像表示プロトコル（Sixel、iTerm2 inline image、Kitty graphics）
- プラグイン機構とスクリプト言語の埋め込み
- 内蔵エディタとファイルマネージャ
- テーマの配布機構と設定画面の GUI
- 内蔵 SSH クライアントと内蔵シリアルコンソール
- 半透明背景、背景画像、アニメーション付きカーソル
- ハイパーリンク（`OSC 8`）とその起動
- デスクトップ通知（`OSC 777`）
- Kitty キーボードプロトコル

分割を持たない代わりに、複数のエージェントは複数のセッションとして左ペインに並ぶ。
セッションの切り替えがウィンドウ分割の役割を果たす。

## 4. 用語

- **ペイン**：一つの PTY と、その画面状態を持つ実行単位。画面右側の端末領域に一度に一つだけ表示される。
- **セッション**：ペインに、親子関係と起動時の設定を加えたもの。左ペインの木構造の節点にあたる。
- **プロファイル**：ペインを起動する場所と方法を記述した設定の単位。ホスト直接実行と Docker コンテナ内実行のいずれかを表す。
- **fork**：あるセッションから子セッションを作る操作。
- **エージェント ID**：エージェントプロセスが持つ会話の識別子。Claude Code の session ID がこれにあたる。

## 5. 責務の境界

termit はプロセスを起動し、PTY を中継し、エスケープシーケンスを解釈する。
会話の中身、モデル、トークン数、ツール呼び出しについては何も知らない。
エージェント固有の知識は、すべて設定ファイルのコマンドテンプレートに置く。

この境界を守ることが、第 3 節の非目標を維持する条件になる。
端末が会話を理解し始めると、要約表示、コスト表示、履歴の意味づけといった機能が際限なく要求される。
termit は「どのプロセスをどう起動するか」だけを扱い、それ以上には踏み込まない。

## 6. 全体構成

### 6.1 依存

| クレート | 版 | 役割 |
|---|---|---|
| `winit` | 0.30 | ウィンドウと入力イベント |
| `wgpu` | 30 | GPU 描画 |
| `glyphon` | 0.12 | グリフのアトラス管理とテキスト描画 |
| `alacritty_terminal` | 0.26 | VT パーサ、グリッド、スクロールバック |
| `portable-pty` | 0.9 | PTY の生成と子プロセス管理 |
| `serde` と `toml` | 1.x | 設定の読み込み |
| `rusqlite` | 0.3x | コマンド履歴の保存 |

VT エスケープシーケンスの解釈は自前で書かない。
`alacritty_terminal` が持つ `Term` 型に PTY からのバイト列を流し込み、結果のグリッドを読んで描画する。
Docker の制御には API クライアントを使わず、`docker run` の引数列を組み立てて PTY で起動する。

### 6.2 スレッド構成

- **メインスレッド**：winit のイベントループ。入力処理と描画を行う。
- **PTY 読み取りスレッド**：ペインごとに一つ。PTY から読んだバイト列を `Term` に流し、変更があればメインスレッドに再描画を要求する。
- **履歴書き込みスレッド**：一つ。OSC 133 から組み立てたコマンド記録を SQLite に書く。

`Term` は `Arc<FairMutex<Term>>` で共有する。
描画時にロックを取り、グリッドを読み終えたら即座に解放する。

### 6.3 データモデル

```rust
struct Session {
    id: SessionId,            // termit 内部の連番
    parent: Option<SessionId>,
    title: String,            // 表示名。既定は "main" と "fork-N"
    cwd: PathBuf,
    profile: ProfileName,
    agent_id: Option<String>, // エージェント ID。未取得なら None
    pane: Pane,
    state: RunState,          // Running または Exited(code)
}
```

セッションは `Vec<Session>` で保持し、親子関係は `parent` を辿って解決する。
セッション数はたかだか数十であり、木構造を明示的に持つ必要はない。

## 7. fork

### 7.1 何を複製するのか

fork は、親と同じ作業ディレクトリ、同じ環境変数、同じプロファイルで新しいペインを開き、設定に書かれたコマンドテンプレートを展開して実行する。
プロセスの `fork(2)` ではない。
実行中の対話プロセスの内部状態を複製する手段は存在しないため、エージェント自身が持つ会話の再開機能に委ねる。

### 7.2 コマンドテンプレート

設定ファイルは、新規起動と分岐起動の二つのテンプレートを持つ。

```toml
[agent]
new  = "claude --session-id {new_id}"
fork = "claude --resume {parent_agent_id} --fork-session --session-id {new_id}"
```

展開可能な変数は次の四つに限る。

- `{new_id}`：termit が採番した UUID
- `{parent_agent_id}`：親セッションのエージェント ID
- `{cwd}`：作業ディレクトリの絶対パス
- `{parent_title}`：親セッションの表示名

`fork` テンプレートが未設定の場合、fork は親と同じコマンドをそのまま再実行する。
この既定動作により、Claude Code 以外のプロセス（素のシェルを含む）でも fork キーが意味を持つ。

### 7.3 エージェント ID の取得

テンプレートが `{new_id}` を使う場合、termit が採番した UUID がそのままエージェントの会話 ID になるため、ID は起動時点で確定する。
新規起動でも分岐起動でも同じである。

`--resume` と `--fork-session` と `--session-id` を同時に指定できることは実機で確認した。
親 A から分岐し `--session-id B` を渡すと、分岐先の会話は B として保存される。
つまり端末は、分岐先の ID を子プロセスに尋ねる必要がない。

テンプレートが `{new_id}` を使わない場合に備えて、エージェント側から ID を通知する経路も一つ用意する。
OSC 1337 の `SetUserVar` を使う。

```
ESC ] 1337 ; SetUserVar=termit_agent_id=<base64(session_id)> BEL
```

termit は PTY のバイト列からこのシーケンスを検出し、発行元のペインに紐づくセッションの `agent_id` を更新する。
ID を自分で決めるエージェント（起動時に ID を指定できないもの）は、この経路で知らせる。

### 7.4 ID が未取得のときの挙動

`agent_id` が `None` のセッションから fork した場合、`{parent_agent_id}` を展開できない。
このとき termit は `fork` テンプレートを使わず、親と同じコマンドを同じ作業ディレクトリで起動する。
左ペインには、そのセッションが会話を引き継いでいないことを示す印を出す。

暗黙にコマンドを書き換えたり、エラーで起動を拒否したりはしない。
利用者が意図した「もう一つ立ち上げる」は必ず成功し、会話が継がれたかどうかは表示で区別できる。

## 8. Docker サンドボックス

### 8.1 プロファイル

プロファイルは、ペインをどこで動かすかを記述する。
既定のプロファイル `host` はホスト上で直接起動する。
それ以外のプロファイルは Docker コンテナ内で起動する。

```toml
[profile.sandbox]
image   = "tex-agent:latest"   # claude をインストール済みのイメージ
workdir = "/work"
mount   = ["{cwd}:/work"]
network = "bridge"
env     = ["ANTHROPIC_API_KEY"]
args    = ["--dangerously-skip-permissions"]
```

各項目の意味は次のとおり。

**image**：使用するイメージ。

**workdir**：コンテナ内の作業ディレクトリ。

**mount**：`docker run -v` に渡すマウント指定。`{cwd}` を展開する。

**network**：`docker run --network` に渡す値。既定は `bridge`。

**env**：ホストから引き継ぐ環境変数名。値ではなく名前だけを書く。

**args**：テンプレートを展開したコマンドの末尾に付ける引数。

### 8.2 起動コマンドの組み立て

プロファイル `sandbox` でエージェントを新規起動する場合、実行されるのは次の引数列になる。

```
docker run --rm -it \
  -v /Users/tkc/repo:/work -w /work \
  --network bridge \
  -e ANTHROPIC_API_KEY \
  tex-agent:latest \
  claude --session-id <uuid> --dangerously-skip-permissions
```

隔離の根拠は、ネットワークの遮断ではなくマウント範囲とプロセス名前空間にある。
コンテナから見えるファイルは `mount` に書いた範囲だけであり、ホストの他のディレクトリ、ホストのプロセス、ホストにインストールされたコマンドには届かない。
権限確認を省く `--dangerously-skip-permissions` を使えるのは、この範囲の限定が効いているときに限る。

`network` の既定を `bridge` とするのは、モデル API への接続が切れるとエージェントが動かないためである。
外部へ出る必要のないプロセスには `network = "none"` を明示的に指定する。

termit は `network` と `args` の組み合わせを検査しない。
どの隔離が必要かはエージェントと作業の性質で決まり、端末が判定できる事柄ではない。

### 8.3 fork との関係

プロファイルと fork は互いに独立している。
fork は既定で親のプロファイルを継承する。
プロファイルを指定した fork は、親の会話を継ぎつつ実行場所だけを変える。
ホストで作業を進めたエージェントを、危険な操作の直前だけサンドボックスへ移す使い方を想定している。

コンテナ内で起動する場合、`{cwd}` はホスト側の絶対パスとしてマウント指定に展開され、エージェントに渡す作業ディレクトリは `workdir` の値になる。

## 9. コマンド履歴

### 9.1 何を記録するのか

シェルの `HISTFILE` を読まない。
端末自身が OSC 133 のシェル統合マークを解釈して記録する。

| シーケンス | 意味 | termit の動作 |
|---|---|---|
| `OSC 133;A` | プロンプト開始 | 直前のコマンドを確定して保存する |
| `OSC 133;B` | コマンド入力開始 | 入力開始位置を記録する |
| `OSC 133;C` | コマンド実行開始 | 開始時刻を記録する |
| `OSC 133;D;<code>` | コマンド終了 | 終了コードと所要時間を確定する |

コマンド文字列は、`B` と `C` の間のグリッド内容から復元する。
作業ディレクトリは OSC 7 の通知から取る。

シェル統合が入っていない環境では、これらのシーケンスが来ないため履歴は記録されない。
その場合、左ペインの履歴欄には設定手順への案内を一行出す。

### 9.2 保存形式

`~/.local/share/termit/history.db` に SQLite で保存する。

```sql
CREATE TABLE command (
  id         INTEGER PRIMARY KEY,
  session_id INTEGER NOT NULL,
  agent_id   TEXT,
  cwd        TEXT NOT NULL,
  command    TEXT NOT NULL,
  exit_code  INTEGER,
  started_at INTEGER NOT NULL,  -- Unix ミリ秒
  duration_ms INTEGER
);
CREATE INDEX idx_command_started ON command(started_at DESC);
CREATE INDEX idx_command_session ON command(session_id, started_at DESC);
```

JSONL ではなく SQLite を選ぶ理由は、絞り込み検索を全件読み込みなしで行うためである。
数万件の履歴に対して、入力のたびに前方一致と部分一致を引く。

### 9.3 検索

`Ctrl+R` で画面下部に一行の検索欄を出す。
入力に対して部分一致で絞り込み、新しい順に最大 20 件を表示する。
`Enter` で選択したコマンドを現在のペインの PTY へ書き込む。
実行はしない。
利用者が内容を確認してから `Enter` を押す。

検索の既定範囲は全セッションとする。
`Ctrl+R` を続けて押すと、現在のセッションのみ、現在の作業ディレクトリのみ、と範囲を切り替える。

## 10. 左ペイン

**左ペインは端末の文字グリッドとは別に、画素で組む。**
端末はセルの格子に縛られるが、一覧は縛られない。
段ごとに文字サイズを変え、余白を pt で指定し、角を丸められる。

幅は既定 200pt とし、設定で変えられる。
**境目を掴んで動かすと、その場でも変えられる。**
掴める幅は境目から左右 4pt とし、その上ではカーソルの形を変えて掴めることを示す。
変えた幅はそのウィンドウのあいだだけ効く。設定ファイルへは書き戻さない。
端末はその次の桁から始まるので、端数として 1 桁未満の隙間ができる。

書体は端末とは別に、等幅でないものを使う。
同じ幅に入る文字数が増え、パスが切れにくくなる。
Warp も一覧には等幅でない書体を使っている。

```
                             +

● ~/github/terminal_tex    ⌘1
  ✻ シンプルターミナル仕様書
  ⋔ main

└ ● ~/github/terminal_tex*  ⌘2
    ✻ 配色の実測
    ⋔ main
──────────────────────────────
 0 cargo test
 0 git status
```

### 10.1 寸法

Warp の一覧を画素から測った値に合わせた（実測は `docs/warp-metrics.md`）。
単位は pt で、描くときに表示の倍率を掛ける。

| 項目 | 値 |
|---|---|
| ペインの幅 | 200 |
| 行の矩形の左余白 | 6 |
| 行の矩形の右余白 | 8 |
| 矩形と矩形のあいだ | 4 |
| 矩形の上端から 1 段目まで | 9 |
| 最後の段から矩形の下端まで | 10 |
| 実行状態の印の左端 | 7 |
| 文字の左端 | 20 |
| 分岐 1 段ぶんの字下げ | 12 |
| 角を丸める半径 | 6 |
| 見出しの帯の高さ | 34 |

行の高さは、段の数と各段の文字サイズから決まる。
3 段のとき 9 + (16.9 + 15.6 + 13) + 10 = 64.5pt となり、Warp の実測 65pt と一致する。

### 10.2 文字サイズ

| 段 | サイズ |
|---|---|
| 名前 | 13pt |
| 名乗った題名 | 12pt |
| ブランチ名 | 10pt |
| 直近のコマンド | 11pt |

**切り詰めは文字数ではなく実際の幅で判断する。**
等幅でない書体では、文字数の見当は大きく外れる。
整形した幅を測り、比から当たりを付けて調整する。
パスは末尾のほうが手がかりになるので先頭を落とし、それ以外は末尾を落とす。

### 10.3 段の中身

1 段目は名前、`⌘` の番号を並べる。
実行状態の印は左端に置く。Warp がアバターを置いている位置にあたる。
`●` が実行中、`○` が終了で、終了コードが 0 でなければ赤にする。
会話を引き継いでいない分岐には、名前の後ろに `*` を付ける。

右端はふだん `⌘` の番号を出し、カーソルが乗っているあいだは閉じる印に変わる。
両方を常に置くと名前の幅が足りない。
Warp も同じく、ふだんは番号、乗せると別の印に変える。

名前は、何もしなければ作業ディレクトリとする。
`$HOME` は `~` に縮める。
`⌘I` で名前を付けられ、空にすると作業ディレクトリの表示へ戻る。
名前はそのセッション限りで、閉じると消える。

2 段目は端末上のプログラムが `OSC 0` で名乗った題名を出す。
Claude Code は作業の題名をここへ送るため、何をしているセッションかが分かる。
名乗っていなければ段そのものを作らない。

3 段目はブランチ名を出す。
git の作業ツリーの下にいないときは、この段そのものを作らない。

**作業ディレクトリは、OSC 7 と OS への問い合わせの両方で追う。**

OSC 7 だけに頼ると、シェル統合を入れていない利用者では起動時の位置から動かない。
macOS の `/etc/zshrc` は `/etc/zshrc_$TERM_PROGRAM` を読む作りで、
`Apple_Terminal` のときにだけ OSC 7 を出す仕組みが入る。
`TERM_PROGRAM` が別の値である以上、誰も出さない。

そこで、前面にいるプロセスの pid を PTY から得て、その作業ディレクトリを
OS に尋ねる（macOS では `proc_pidinfo` の `PROC_PIDVNODEPATHINFO`）。
シェルが別のプログラムを起動していればそちらの pid になるので、
`vim` の中にいるときはその作業ディレクトリが出る。

尋ねるのは走っているセッションだけ、400ms に 1 回までとする。
OSC 7 が届く環境では、そちらが先に変化を捉える。
どちらが先でも同じ値に落ち着く。

作業ディレクトリが変わったら、覚えている並びも書き直す。
ブランチ名は `git` を起動せず `.git/HEAD` を読んで得る。
左ペインは毎秒描き直すので、そのたびにプロセスを起こすわけにはいかない。
作業ディレクトリが変わったときと、2 秒以上経ったときだけ読み直す。

分岐の印には `⋔`（U+22D4）を使う。
等幅フォントに含まれ、分岐として読める字形をいくつか並べて比べたうえで選んだ。

**見出しの文字は置かない。**
区切り線の上下がそれぞれ何かは、並んでいるものを見れば分かる。
名札を付けても、置き場所を一度覚えたあとは読まれない。
同じ理由で、直近コマンドが無いときの案内文も出さない。
直近コマンドが無ければ区切り線ごと出さない。

新規セッションの目印は、見出しの帯の右端に `+` を置く。

**端末との境目に線は引かない。**
地の色が違うので、線がなくても境目は分かる。
文字グリッドの上に縦線を引くと、字と字のあいだで途切れて破線に見える。

`^B` で左ペインの表示と非表示を切り替える。

## 10.4 セッションの復元

**セッションの並びを覚えておき、次の起動で作り直す。**
当初は非目標に挙げていたが、複数のエージェントを並べて使う以上、
起動のたびに並べ直すのは実用に耐えないため方針を改めた。

覚えるのは、作業ディレクトリ、プロファイル、名前、会話 ID、親子の関係、
プロファイルで包む前の起動コマンド、そして選んでいた位置である。
`$XDG_DATA_HOME/termit/sessions.toml` へ書き、並びが変わるたびに書き直す。

プロセスそのものは復元できない。
会話 ID が分かっていて `[agent] resume` があれば、それで会話を再開する。
無ければ、覚えていたコマンドをそのまま動かす。

書き出しは 500ms に 1 回までに抑える。
作業ディレクトリは `OSC 7` で頻繁に変わるため、そのたびに書くと無駄が多い。
一時ファイルへ書いてから置き換えるので、途中で落ちても半端な内容は残らない。

読めない、版が違う、親が自分より後ろを指している、といった内容は捨てて、
いつもどおり 1 つ立ち上げる。
覚えていた作業ディレクトリが無くなっている場合は home へ落とす。

`window.restore_sessions` を `false` にすると、この動作をやめる。

## 11. 操作

### 11.0 表記

**画面に出る文字は英語にする。**
端末の中身は子プロセスの領分であり、端末自身が出す文字だけが対象である。
誤りの知らせや記録の出力も含める。

最下段の帯は 11pt とし、端末の文字（13pt）より小さくする。
書体も端末とは別の、等幅でないものを使う。
端末の中身ではなく端末についての表示なので、桁に揃える必要がない。
同じ大きさで並べると、本文より目立ってしまう。

### 11.1 キーバインド

割り当ては二系統ある。
Ctrl 側はこの端末の操作で、シェルとエージェントから 6 個だけ奪う。
Cmd 側は macOS の作法に合わせたもので、シェルもエージェントも Cmd を使わないため何も奪わない。

| キー | 動作 |
|---|---|
| `^O` | 新規セッション |
| `^\` | 選択中セッションを fork |
| `^]` | プロファイルを選んで fork |
| `^^` | 左ペインの選択を次へ（巡回する） |
| `^B` | 左ペインの表示切り替え |
| `^R` | コマンド履歴検索 |
| `⌘N` / `⌘D` / `⌘E` | 新規 / fork / 選んで fork |
| `⌘[` / `⌘]` | 左ペインの選択を前 / 次へ |
| `⌘1` から `⌘9` | その番号のセッションへ |
| `⌘F` | 画面とスクロールバックの中を探す |
| `⌘I` / `⌘⇧R` | セッションに名前を付ける |
| `⌘K` | 画面とスクロールバックを消す |
| `⌘W` | セッションを終了 |
| `⌘C` / `⌘V` | コピー / 貼り付け |
| `⌘=` / `⌘-` | フォントサイズ |
| `Shift+PageUp` / `PageDown` | スクロール |

`⌘K` は、スクロールバックを端末側で捨てたうえで、シェルへ `\x0c`（Ctrl+L）を送る。
画面の消去とプロンプトの出し直しはシェルに任せる。
端末が画面を消すだけでは、プロンプトが消えたまま戻らない。
この動作は macOS の alacritty の既定に合わせた。

これ以外のキー入力は、すべてそのまま PTY へ渡す。
修飾キーの組み合わせを端末が横取りする範囲を最小限にとどめ、エージェントやエディタが使うキーを奪わない。

**Shift を要求する組み合わせは作らない。**
macOS では `Ctrl` と `Shift` の同時押しが端末まで届かないことがある。
実機で確認したところ、`ctrl` と `shift` が同時に立った入力は一度も届かなかった。
片方だけが届くため、`Ctrl+Shift+英字` を割り当てると必ず外れる。

照合には修飾を外したキーを使う。
`Ctrl` を押した時点で論理キーが制御文字になる環境があるためである。
配列によって文字が取れない場合に備えて、物理キーでも照合する。

キーが届いているかどうかは `termit --keytest` で確かめられる。
押したキーの論理キー、修飾を外したキー、物理キー、修飾キー、一致した動作を画面に並べる。

### 11.2 マウス

マウスが働くのは左ペインと端末領域だけである。

| 操作 | 動作 |
|---|---|
| 左ペイン見出しの `[+]` | 新規セッション |
| 左ペインの行 | そのセッションへ切り替え |
| 行の `×` | そのセッションを終了 |
| 端末をドラッグ | テキストを選択 |
| 端末をダブルクリック | 単語を選択 |
| 端末をトリプルクリック | 行を選択 |
| ホイール | スクロール |

選択は `alacritty_terminal` の `Selection` に持たせ、描画では背景色を置き換えて示す。
前景と背景を入れ替える方式は、全角文字や太字が混ざると読みにくい。
選択したテキストは自動ではコピーしない。
`⌘C` を押したときだけクリップボードへ入れる。

### 11.3 画面の検索

`⌘F` で最下行に検索欄を出す。
打つたびに探し直し、見つかった箇所をその場で強調する。
行を絞り込む方式は取らない。
画面の並びが崩れると、前後の文脈から探しているものを見つけられなくなる。

探索は `alacritty_terminal` の `RegexSearch` に任せる。
既定では入力の特殊文字を打ち消してそのままの文字列として探し、`Tab` で正規表現へ切り替える。
大文字を含まない入力は大小を区別しない（`RegexSearch` の既定の挙動）。

最初の探索と `Enter` は古い方（上）へ進む。
端末では新しい出力が下にあり、探したいものはたいてい上にあるためである。
`⇧Enter` で新しい方へ戻る。

強調するのは見えている範囲だけとする。
`RegexIter` で可視範囲を走査し、セルの集合に直してから描く。
スクロールバック全体の一致数は数えない。
1 万行を毎フレーム走査する費用に見合わない。

一致は黄 `#F1FA8C`、いま選んでいる一致は橙 `#FFB86C` で示し、文字は `#282A36` に落とす。
検索の強調は選択より優先する。探しているものを見失わないためである。

### 11.4 変換を伴う入力

変換を伴う入力（IME）の確定文字列は、キー入力ではなく専用の通知で届く。
開いている入り口（画面の検索、コマンド履歴の検索）があればそちらへ渡し、
なければ子プロセスへ送る。

変換中の文字列は、確定するまでどこへも渡さない。
そのままでは何を打っているか見えないので、文字が入る位置に描く。
確定した文字と見分けられるよう、地を一段明るくして下線を引く。
候補窓の位置も同じ場所へ寄せる。

変換中はカーソルの塗りを出さない。
塗りが変換中の一文字目に重なると、何を打っているか読めなくなる。
文字が入る位置は変換中の文字列の末尾なので、そこに細い棒を出す。

変換中はキー入力からの文字を取らない。
両方から取ると同じ文字が二度入る。

この扱いを落とすと、日本語で検索できないという形で現れる。

この方式は Warp の Find に合わせた。
Warp も行を絞り込まず、ペインの中を下から上へ探し、正規表現と大小区別の切り替えを持つ。

### 11.5 端末上のプログラムへの受け渡し

端末が横取りするか、そのまま渡すかは、プログラムが要求している状態で決める。

`?1000` `?1002` `?1003` のいずれかが設定されているあいだ、クリックとホイールはプログラムへ渡す。
形式は `?1006` が設定されていれば SGR、そうでなければ旧来の 1 バイト表現を使う。
旧来の形式は 223 桁までしか表せないため、それを超える位置は送らない。
移動の報告は、`?1003` なら常に、`?1002` なら釦を押しているあいだだけ送る。
同じセルの中の動きは送らない。

**Shift を押しているあいだは渡さず、端末側の選択に使う。**
これは xterm からの作法で、報告中でも文字を選べるようにするためである。

`?1004` が設定されていれば、ウィンドウの出入りで `CSI I` と `CSI O` を送る。

代替画面に入っていて、かつマウスを要求していない場合、ホイールは矢印キーへ変換する。
`less` や `man` はこれがないとまったくスクロールできない。

`OSC 0` と `OSC 2` で名乗った題名は、ウィンドウの題名にする。
左ペインの名前はセッションの識別なので置き換えない。

これらの取捨は、エージェントの全画面 UI が実際に出す並びを実測して決めた。
Claude Code は起動時に `?1000` `?1002` `?1003` `?1004` `?1006` `?1049` `?2004` を設定し、
`OSC 0` で題名を名乗り、`CSI c` で装置属性を問い合わせる。
Kitty キーボードプロトコルは要求しない。

## 12. 描画

### 12.1 方式

`alacritty_terminal` の `Term` からグリッドを読み、可視領域のセルを `glyphon` のテキストバッファへ変換して描画する。
セルの背景色は、同色が連続する区間を矩形にまとめて別パスで塗る。

再描画は、PTY からの更新があったフレームと、入力があったフレームだけ行う。
更新のないあいだは `winit` を待機状態に置き、CPU を使わない。

### 12.2 目標値

- 起動から最初のプロンプト表示まで 200ms 以内
- 1 ペイン待機時の常駐メモリ 100MB 以内
- 80x24 の全画面書き換えを 16ms 以内

スクロールバックは既定 10000 行、設定で変更可能とする。

現状の実測値（macOS、release ビルド、単一ペイン）は次のとおりである。

| 項目 | 目標 | 実測 |
|---|---|---|
| 起動から子プロセスの生成まで | 200ms | 224ms（3 回の中央値、199 から 337ms） |
| 常駐メモリ | 100MB | 84.7MB |
| バイナリ | 単一ファイル | 9.4MB |
| 80x24 の全画面書き換え | 16ms | 1.1ms |
| 入力の往復（PTY の echo からグリッド反映まで） | — | 0.073ms |
| 更新の読み取りから present まで | — | 0.5〜1.3ms |

工程ごとの内訳と測り方は [performance.md](../../performance.md) に記録した。
表示までの待ちが支配的で、`desired_maximum_frame_latency` を 1 にしてある。

起動時間は目標をわずかに超えている。
支配的なのはフォントデータベースの走査であり、字形の代替を効かせるために
システムのフォントを読む必要がある。
縮めるなら、代替に使う候補を絞って読み込む方向になる。

### 12.3 フォント

等幅フォントのみを扱う。
既定は `Menlo` とする。
macOS に同梱される SF Mono はアプリケーションバンドルの中にあり、フォントデータベースから名前で引けないため既定にしない。
設定されたフォント名が見つからない場合は総称の等幅フォントへ落とす。
セル幅はフォントの advance から一度だけ決め、以後は全セルで同じ値を使う。
East Asian Width が Wide の文字は 2 セルを占める。
合字と可変幅は扱わない。

### 12.4 配色

配色は Dracula を基にする。
端末の基本色は Dracula の値をそのまま使い、画面各部の色は Warp の実装を実測した値に合わせた。

**面は 3 段階**とし、手前にあるものほど明るくする。

| 用途 | 値 |
|---|---|
| 端末の地 | `#282A36` |
| クローム（左ペイン、状態行） | `#32343F` |
| 浮いた面（選択行、重ねた一覧の選択） | `#3C3E48` |

左ペインを端末より**明るく**する点に注意する。
暗くすると奥に沈んで見え、常時表示する一覧としては読みにくい。

**文字も 3 段階**とし、情報の階層を明度で示す。

| 用途 | 値 |
|---|---|
| 主（コマンド、実行中セッション名） | `#F8F8F2` |
| 副（見出し、停止中の項目、一覧の非選択行） | `#B0B1B0` |
| 三次（終了コード、罫線、ヒント、補助記号） | `#8A8B90` |

**ANSI 16 色は Dracula の値**を使う。
背景 `#282A36`、前景 `#F8F8F2`、赤 `#FF5555`、緑 `#50FA7B`、黄 `#F1FA8C`、
青 `#BD93F9`、紫 `#FF79C6`、水 `#8BE9FD`。

選択したセルは前景色を変えず、背景を `#44475A` に置き換える。
前景と背景を入れ替える方式は、全角文字や太字が混ざると読みにくくなる。

強調は緑 `#50FA7B`（実行中、`[+]`）と赤 `#FF5555`（非ゼロの終了コード、エラー）の 2 色に限る。

## 13. 設定ファイル

`~/.config/termit/config.toml` を読む。
存在しない場合は組み込みの既定値で動く。
起動時に一度だけ読み、実行中の再読み込みは行わない。

```toml
[window]
font        = "Menlo"
font_size   = 13.0
scrollback  = 10000

[shell]
program = "/bin/zsh"
args    = ["-l"]

[agent]
new  = "claude --session-id {new_id}"
fork = "claude --resume {parent_agent_id} --fork-session --session-id {new_id}"

[profile.host]
# 既定。docker を使わない

[profile.sandbox]
image   = "tex-agent:latest"
workdir = "/work"
mount   = ["{cwd}:/work"]
network = "bridge"
env     = ["ANTHROPIC_API_KEY"]
args    = ["--dangerously-skip-permissions"]
```

設定は `$XDG_CONFIG_HOME`、なければ `~/.config` の下を見る。
macOS の `dirs::config_dir()` は `~/Library/Application Support` を返すが、
端末の利用者が設定を探すのはそこではない。
履歴も同様に `$XDG_DATA_HOME`、なければ `~/.local/share` の下に置く。

設定の誤りは起動時に検出し、該当行を示して終了する。
不正な値を既定値で補って黙って起動することはしない。

## 14. エラー処理

**プロセスの起動に失敗した**：ペインを作らず、左ペインに一行のエラーを出す。ウィンドウは維持する。

**プロセスが終了した**：ペインの内容を残したまま `Exited(code)` に遷移する。左ペインには終了コードを表示する。同じ位置で `Enter` を押すと同じ設定で再起動する。

**docker が見つからない**：`host` 以外のプロファイルを選んだ時点で検出し、起動を中止して案内を出す。

**設定が壊れている**：起動時に終了コード 1 で停止し、問題のある項目を示す。

**履歴 DB が開けない**：履歴機能だけを無効にして起動を続ける。端末としての機能は落とさない。

## 15. テスト方針

GPU 描画を伴う部分は自動テストの対象外とし、それ以外を単体テストで覆う。

- コマンドテンプレートの展開：変数の置換、未定義変数の扱い、fork テンプレート未設定時のフォールバック
- Docker 引数の組み立て：プロファイルから `docker run` の引数列を作る関数の入出力
- OSC 1337 `SetUserVar` の検出と base64 復号
- OSC 133 の状態機械：`A` から `D` までの遷移と、途中で分断されたバイト列の扱い
- 履歴 DB のクエリ：絞り込みと範囲切り替え
- 設定の読み込みと検証：不正な値がエラーになること

PTY を伴う結合テストを一つ置く。
`/bin/echo hello` を起動し、グリッドに `hello` が現れ、プロセスが終了コード 0 で `Exited` に遷移することを確認する。

## 16. ビルドと配布

対象は macOS を先に完成させ、Linux を後追いする。
Windows は対象外とする。

必要なものは Rust の安定版ツールチェーンだけとする。

```
cargo build --release
```

生成物は単一バイナリ `target/release/termit` とする。
アプリケーションバンドルの作成は任意とし、バイナリ単体で動くことを保証する。

## 17. 段階的な実装順序

各段階の終わりで動くものが残るように分ける。

1. **ウィンドウと描画**：winit と wgpu を初期化し、glyphon で固定文字列を表示する。
2. **PTY と VT**：シェルを起動し、`alacritty_terminal` を経由してグリッドを描画する。キー入力を PTY へ渡す。
3. **セッションと左ペイン**：複数ペインを持ち、左ペインに一覧を出し、切り替える。
4. **fork**：テンプレート展開を実装し、系統樹に親子関係を出す。ID を自分で決めるエージェント向けに OSC 1337 の検出も入れる。
5. **プロファイル**：`docker run` の引数組み立てを実装する。
6. **履歴**：OSC 133 の状態機械、SQLite への保存、`Ctrl+R` の検索を実装する。
7. **仕上げ**：設定の検証、エラー処理、フォントサイズ変更、コピーと貼り付け。

## 18. 前提と未確認事項

**前提**：macOS を主対象とする。設定は TOML とする。等幅フォントのみを扱う。セッションは永続化しない。

**確認済み**：`claude --resume <A> --fork-session --session-id <B>` は受け付けられ、分岐先の会話が B として保存される。
第 7.3 節はこの結果に基づく。

**確認済み**：`glyphon` 0.12 は `wgpu` 30 に依存しており、版は整合する。

**確認済み**：`alacritty_terminal` 0.26 の `Term` へは `vte::ansi::Processor::advance` で任意のバイト列を流せる。
これにより PTY の生バイト列を端末側で保持でき、OSC 133 と OSC 7 と OSC 1337 を自前で拾える。

**制限**：コマンド文字列は、`OSC 133;B` の時点のカーソル位置から `OSC 133;C` の時点のカーソル位置までをグリッドから読んで復元する。
入力の途中で画面がスクロールして開始位置が失われた場合は、実行直前の行だけを読む。
